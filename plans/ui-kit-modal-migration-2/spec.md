# Tech Spec: UI kit modal migration 2 (ui-kit-modal-migration-2)

## Overview
Every remaining hand-rolled modal moves onto `ui/kit/` (`ModalController` + `modalFrame` + `modalCss`/`buttonCss`). Each one drops its own `document` keydown, `role="dialog"` markup and frame/button CSS, so `tools/ui-kit-baseline.json` shrinks to the three non-modal entries. Two kit hooks that were only stubbed get finished: Ctrl/⌘+Enter in textarea modals (R12, already in the router) and the dirty guard, which gains a stacked `ed-confirm` "Discard unsaved changes?" prompt with a `cancelLabel`. Kit additions are small and additive: `cancelLabel` and `focusCancel` frame options, a pure `isDirty` helper, and a scoped-CSS helper so the one portal modal that must stay in light DOM (`ed-save-key`) can still use the kit. No game value, rule, schema or engine file is touched.

## Guardrail alignment
- **Tier 1:** one item only, the UI-GUIDELINES §7 line "Textarea modals: Enter types a newline; Ctrl/⌘+Enter saves". Owner sign-off: qa-log 2026-11-20T09:21:00Z. Quote it in the PR. No other UI-GUIDELINES edit.
- **Tier 3:** everything else (kit-conformant modal migrations, additive `ed-confirm` prop, kit helpers, MODALS.md, UI-CONSISTENCY-REVIEW.md status lines, baseline, changelog). Tier 2 (taxonomy) not triggered; engine, `rules/*.json`, character data and schema untouched.
- **Golden rule holds:** every migrated view still only dispatches events up (`ed-edit-notes`, `ed-edit-meta`, `ed-conflict`, `ed-settings`, ...). Draft values are UI state only; nothing new is stored. The kit never dispatches game events. `modal-controller.js`/`modal-stack.js` stay lit-free and DOM-light; the new `ui/kit/dirty.js` and `ui/kit/scope-css.js` are pure. No derived values are added, so no placeholder pills are needed.
- **Correction to the plan (F1), not a guardrail issue:** `ModalController.focusInitial` focuses the enabled **primary** before `initialFocus` for `confirm`/`input` kinds, so `ed-confirm`'s `initialFocus: '[data-cancel]'` only takes effect when the primary is disabled. With the plan as written, Enter on the discard prompt would hit **Discard**, not Keep editing. The spec fixes this with a `focusCancel` option (see Design). No human decision needed.

## Design
### Data / types
None stored. New transient UI state only (each host's snapshot / prompt flag). New public properties and options:
- `ed-confirm`: `cancelLabel` (String, default `"Cancel"`), `focusCancel` (Boolean, default false).
- `modalFrame` opts: `cancelLabel` (default `'Cancel'`), `focusCancel` (default `false`; stamps `autofocus` on the Cancel button, which `focusInitial` honours first).

### Modules & functions
**Kit (all under `ui/kit/`)**
- `modal.js`: add `cancelLabel` / `focusCancel` options (Cancel button renders `${cancelLabel}` and `?autofocus=${focusCancel}`). Add `export function ensureLightStyles()`: idempotently (module flag) builds one `CSSStyleSheet` from `scopeCss(modalCss cssText, '.kit-portal')` and pushes it onto `document.adoptedStyleSheets`. `modalCss` is an array of `CSSResult`; join their `.cssText`.
- `scope-css.js` (new, pure, no lit/DOM): `export function scopeCss(cssText, scopeSelector)` returns `` `${scopeSelector} { ${cssText} }` `` (native CSS nesting; a relative selector like `.overlay` nests as a descendant). Unit-tested.
- `dirty.js` (new, pure): `export function isDirty(snapshot, draft)`. Compares the union of keys of two plain objects; each value is normalised with `null/undefined -> ''`, numbers/booleans -> `String(v)`, objects/arrays -> `JSON.stringify(v)`; **no trimming** (a trailing space is a change). Returns true when any key differs. Typing a value back to the original gives false.
- `modal-controller.js`: no change expected. `isDirty`/`onDiscardPrompt` already exist and are already tested; the `light` option already exists (`_root()` returns `document`). If implementation shows a gap, any change stays lit-free and gets a test.

**`ui/ed-confirm.js`**: add the two properties; pass `cancelLabel`/`focusCancel` to `modalFrame`. Defaults keep every existing use unchanged (still "Cancel", still `initialFocus: '[data-cancel]'`).

**Shared discard-prompt pattern (I1b/I2), used identically by Notes (note + event), Edit character details and Custom items**
```js
// host: ctl = new ModalController(this, { kind:'input', isDirty: () => isDirty(this._snap, this._draft()),
//   onDiscardPrompt: () => { this._discard = true; }, onConfirm: () => this._save(), onClose: ... });
// render (after the frame, same shadow root, so it stacks above at equal layer):
html`<ed-confirm heading="Discard unsaved changes?" message="..." confirmLabel="Discard"
  cancelLabel="Keep editing" focusCancel
  @confirm=${() => { this._discard = false; this._ctl.close(); }}   // unguarded close of the host modal
  @close=${() => { this._discard = false; this._ctl.refocus(); }}></ed-confirm>`
```
- Escape on the prompt, its Keep editing button and its ✕ all emit `close` (cancel), so they return to editing. The host modal is never closed by the prompt's Escape (kit stack top-only).
- **Focus return to the field:** the text field carries `autofocus`, so `refocus()` (which runs the same order as open; `[autofocus]` wins) lands on the textarea. `ed-confirm` restores focus to its own trigger (the field or ✕ that was focused) first; the host `@close` handler then runs `refocus()` afterwards, so the field ends up focused. Pointer-driven closes (✕/backdrop) behave the same.
- Snapshot: taken when the modal opens (`_snap = { ... }` from the stored entry / meta / opened state); false again after a successful save (the modal is removed) and after Discard.

**`ui/ed-settings.js`, `ui/ed-conflict.js` (move into the normal shadow root) and `ui/ed-save-key.js` (stay light DOM): I1 decision**
- Why the portal existed: `ed-conflict`/`ed-settings` comments say "always sits above everything"; `ed-save-key`'s comment says the credential field must be at document level so Safari/iCloud Keychain autofill works (it does not pierce shadow DOM). All three are mounted at the top level of `ed-app`'s template (`ed-app.js` ~2089-2102), the same place as `ed-confirm` (2100) and the roll modal (3000), and no ancestor creates a stacking context (`ed-app` `:host` is plain `display:block`; the only `transform` is on the fixed toast).
- **`ed-conflict` and `ed-settings`: drop `createRenderRoot()`**, use `static styles = [modalCss, css...]`, `modalFrame(..., { layer: 2200 })`. Layering is kept by the explicit `layer`.
- **`ed-save-key`: keep the light-DOM portal** (autofill requirement), set its portal div class to `kit-portal`, call `ensureLightStyles()` in `connectedCallback`, controller option `{ light: true }`, `layer: 2100`. Delete its inline `<style>` frame CSS; keep only the field CSS it still needs (`.edk-user` off-screen, `.edk-input`, `.edk-label`, `.edk-hint`), scoped under `.kit-portal`. `--fs-*` tokens come from `:root` in `index.html`, so they resolve in light DOM.
- **Fallback if V1.6 fails** (conflict not on top of an open modal): switch only that modal to the same light-DOM path as `ed-save-key`. It is built anyway, so the fallback is free.
- All three open the controller from `connectedCallback`: `this._ctl.opened(deepActiveElement())` (same as `ed-confirm`; no `ed-app` change). `data-modal` ids are unique per controller, which `light: true` needs.

### UI / behavior
- Every migrated modal: Escape closes top only; Enter = OK (read-only: closes); backdrop, ✕, Cancel are one cancel path; focus returns to trigger; footer `[Cancel] [Primary]` and the kit's fixed hint on input/confirm modals; read-only modals ✕ only.
- Textarea modals (Notes note, Notes event, Edit details, Custom item form): hint "Ctrl+Enter saves · Esc = Cancel"; Enter in a textarea types a newline; Ctrl/⌘+Enter saves; single-line inputs in the same modal keep Enter = save.
- Discard prompt: dirty Escape/✕/backdrop/Cancel opens the stacked prompt; Cancel is focused so Enter = Keep editing (the kit hint on the prompt still reads "Enter = OK", accepted since the text is fixed by the kit).
- Light and dark: all colours come from `modalCss`/`buttonCss` `light-dark()` fallbacks; the light-DOM save-key relies on the same via the scoped sheet. Karma Ritual primary uses the `karma` tone; day-reset the `heal` (green) tone. Overview must still fit the desktop viewport with no vertical scroll (modals are fixed overlays and add no layout).
- Modal Escape/Enter behaviour is wholly the kit's; the hosts hold no key handlers.

### Edge cases & invariants
- `isDirty({a:'x'},{a:'x'})` false; `null`/`undefined`/`''` equal; `5` equals `'5'`; extra keys on either side count; typing a change then reverting is clean; trailing space is dirty.
- A clean modal closes straight away; a dirty one never closes on Escape without the prompt; `ctl.close()` is always unguarded (used by Discard and by saves).
- After save, the modal is removed, so a reopen takes a fresh snapshot (no prompt).
- Edit details on a non-Ork meta has no Gahad fields: snapshot only includes keys that are rendered.
- Stacking: conflict (2200) must render over any open kit modal. An `ed-confirm` (2100) is a sibling at a lower z-index than Settings (2200), so one opened while Settings is open would render beneath it (the kit stack would still give it Escape). Settings has no path that opens a confirm today (V1.5 says "if reachable"); if the owner finds one, that is a finding to log, not a reason to lower Settings.
- The `ed-confirm` discard prompt and its host share layer 2100; the prompt must be rendered **after** the frame so DOM order puts it on top. Notes' `_confirm` is already rendered last.
- Custom item "Discard" wording: uses "Close" because edits persist in the browser overlay (flagged below as a minor deviation from "[Keep editing] [Discard]"; keep unless the owner objects).
- Conflict Cancel/Escape: nothing saved or reloaded; the local draft stays. Enter on "Take theirs" (focus moved by Tab) runs Take theirs, not Keep mine (R13).
- Held-key latch: a modal that closes via a native click after a passed Enter latches that key, as in the first feature; nothing extra to do.
- Portal cleanup: `ed-save-key` still removes its `.kit-portal` div in `disconnectedCallback`, and `hostDisconnected` removes the stack entry.
- Baseline is a two-way ratchet: each file's entry must be lowered/removed in the same change as its migration, or `npm test` fails. End state of `tools/ui-kit-baseline.json` is exactly: `ui/ed-app.js` `{ "button-style": 1 }`, `ui/ed-spells.js` `{ "font-size": 5 }`, `ui/legend-spent-view.js` `{ "font-size": 2 }`. Entries to delete: add-legend, changelog, character-picker, combat, conflict, custom-item, day-reset, edit-meta, homebrew, notes, overview, save-key, settings.
